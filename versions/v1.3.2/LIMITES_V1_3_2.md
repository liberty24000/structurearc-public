# Limites de la V1.3.2 — ce qui est prouvé, ce qui ne l'est pas

Règle suivie : aucune ligne « prouvé » sans commande ni rapport réel dans `preuves/`.

## Prouvé sur le build final (exe `d1f58834fec0…`, installateur standard signé `cd925a1ae42a…`, installateur hors-ligne signé `c75a00283aaf…`, sources `cfd1458d4b01`)
- **Registre : 28 rapports « courant » = 28 PASS** (aucun INCONCLUSIVE ni FAIL parmi eux). Les scénarios qui démarrent un vrai modèle (mission, MCP, actions machine, agents, import GGUF, GPU, changement de modèle, chat automatique) ont tourné avec le vrai Qwen3.5 4B ou Qwen2.5 1,5B sur le GPU.
- **Mission autonome** : 20/20 avec Qwen3.5 4B sur le GPU (appels d'outils enchaînés, commande sensible jamais exécutée sans confirmation, recherche web réelle, proposition de modification non appliquée, arrêt d'urgence). `ui-mcp` : PASS dans la chaîne finale (appel d'un outil MCP par le modèle observé) — voir plus bas : ce comportement est resté irrégulier sur les builds précédents.
- **Installateur** : installation/désinstallation 16/16 ; mise à jour réelle `update-real` 33/33 ; runtime embarqué ; inférence installée PASS. **Installateur hors-ligne** : `offline-installer-check` 9/9 et `model-embed-check` 8/8 (modèle Qwen2.5 1,5B embarqué, taille et SHA-256 vérifiés à l'installation).
- **Tests automatiques** : `test.ps1` PASS au **second** passage (typecheck PASS ; Vitest 158 réussis ; `cargo test --lib` 521 réussis / 0 échec / 6 ignorés ; auto-test moteur, fenêtre native, test de fumée UI, écran IA PASS). Le **premier** passage a échoué pour disque plein (`os error 112`, journal conservé : `test132-1-echec-disque-plein.log`) ; ce n'était pas un défaut du code.
- **Défauts réels trouvés et corrigés pendant cette version** (chacun avec test) : modèle en cours rétrogradé à tort vers un plus petit (estimation « processeur » pour un modèle qui tourne sur le GPU) ; garde GPU qui interrompait toute mission à outils (voir plus bas) ; politique « outils sûrs » (Llama 3.2 3B et 1B écartés des tâches à outils ; 0 essai « sans faux appel » n'est plus jugé sûr) ; ancrage des réponses qui acceptait un chemin inventé ancré par son seul nom de fichier ou un nombre trouvé dans un plus grand ; contrôle anti-fuite du dépôt public qui échouait en silence (options `git grep` dans le mauvais ordre) et chemin local du poste publié dans `releases.json`.
- **Matrice de compatibilité** : colonne « outils sûrs » et état de la mémoire engagée (mesurée ou non), dans l'interface et le journal.

## NON prouvé ou partiel
| Sujet | Réalité |
|---|---|
| **Garde GPU : durée tolérée** | MESURÉ : le préremplissage d'un prompt de ≈ 1 800 jetons sature la carte à 100 % pendant 5 à 7 s quel que soit le nombre de couches déportées. La garde exige donc désormais une charge GPU **soutenue 10 s** avant d'interrompre (CPU et RAM : règle rapide inchangée ; limite de 95 % inchangée). Un prompt de ≈ 8 000 jetons (≈ 25 s de préremplissage) sera encore interrompu. Le choix de la durée est à valider. Mesuré sur UN PC. |
| **MCP piloté par le modèle** | PASS dans la chaîne finale, mais irrégulier sur les builds précédents (le modèle émettait parfois du texte au lieu d'un appel). Cause de l'irrégularité non élucidée. |
| **Ancrage des réponses** | ESTIMATION déterministe (éléments cités retrouvés ou non dans les sources reçues par le modèle), pas une garantie ; « rien de vérifiable » n'est pas « vérifié » ; un fait inventé sans chemin, adresse, identifiant ni nombre n'est pas détecté. |
| **Mémoire engagée (Job Windows)** | Mesurée pour 1 modèle sur 9 (Qwen3.5 4B). Pour les autres, le plafond est une règle prudente (2 × l'estimation, au moins 1,5 Go), pas une observation. La compatibilité automatique « pour tous les PC » n'est pas démontrée. |
| **Très gros modèles / décodage spéculatif / KV quantifié** | NON activés dans l'application. Mesure réelle du décodage spéculatif (brouillon Qwen2.5 0,5B pour cible 1,5B, GPU) : plus lent (0,2 à 0,46 fois) et sorties non identiques sur 2 à 4 prompts sur 5 → abandonné pour cette paire. Le paging d'experts MoE n'est pas mesuré. Aucun gain n'est annoncé. |

| **Capture d'écran / OCR** | Pas de scénario en fenêtre réelle (l'écran de l'utilisateur serait lu). L'écran peut montrer des données d'AUTRES applications : accorder l'autorisation le temps nécessaire seulement. |
