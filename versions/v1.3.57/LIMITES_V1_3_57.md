# Limites connues — StructureArc 1.3.57

Le projet complet local reste non qualifié. Le dernier essai Qwen3.5 4B pendant le développement produit une CLI invalide et ne produit ni les tests ni la documentation demandés. Le contrôle indépendant échoue ; aucune réparation manuelle du projet ni suppression de critère n’a été utilisée. Cet essai conserve l’objectif dans 40 requêtes mesurées malgré huit compressions. Il précède le dernier correctif distinguant les modules importés.

Le contrôle supplémentaire de syntaxe couvre les lancements Node directs reconnus (.js, .cjs, .mjs) et les contrôles explicites --check/-c. Il ne prouve pas la correction fonctionnelle, ni la prise en charge universelle de tous les interpréteurs, options et formulations. Une reprise après échec doit conserver les obligations de vérification ; l’autonomie totale sur tout projet ou tout petit modèle n’est pas démontrée.

Le modèle local 9B n’a pas démarré lors de cet essai, le contrôle de mémoire engagée ayant refusé sa configuration. Cela ne prouve pas une incapacité permanente sur un poste disposant de davantage de ressources.

Le contexte exact est mesuré avec le moteur local reconnu. Le cloud conserve un budget applicatif prudent et une estimation, pas une mesure universelle de sa capacité maximale. Des instructions indispensables trop volumineuses restent une erreur explicite.

Les tests du coffre passent sur le poste Windows de référence ; la cause universelle d’un éventuel défaut Windows n’est pas établie. Les tests ignorés ne sont pas présentés comme réussis. La navigation mobile est contrôlée dans Chrome avec des données de test, sur quatre tailles d’écran ; aucun nouvel essai Android physique ou acoustique n’est revendiqué.

L’installateur public ne contient pas les projets personnels, conversations, mémoires, certificats privés ni clés API. Leur conservation lors d’une mise à jour est contrôlée séparément sur le poste de référence.
