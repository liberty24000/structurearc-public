# Limites connues — StructureArc 1.3.55

L'optimisation du contexte et ses reprises sont vérifiées séparément de la réussite du projet. Les essais Qwen3.5 4B conservent l'objectif, mais la réalisation complète du projet d'acceptation n'est pas encore qualifiée. Lors du dernier essai, trois fichiers sont présents, le programme reste tronqué et le fichier de tests manque ; le vérificateur indépendant échoue. Une sous-étape peut encore produire un bilan partiel sans son livrable nommé. Un plan accepté, un fichier écrit ou une commande exécutée ne suffisent pas à prouver la réussite globale.

La mesure exacte et les corrections de format ciblent le moteur local reconnu. Le parcours cloud conserve ses contrôles et son estimation de contexte ; aucun comptage exact universel n'est revendiqué. Si les instructions incompressibles ne tiennent pas dans la fenêtre, une erreur explicite reste nécessaire.

Une intermittence des tests parallèles du coffre de certificats Windows a été observée. Les mêmes tests passent dans la suite séquentielle complète ; la cause de l'intermittence reste à établir. Aucun test ignoré n'est présenté comme réussi.

Aucun nouveau contrôle physique Android ni essai acoustique n'est revendiqué. Les projets personnels, conversations, mémoires et clés API ne sont pas inclus dans l'installateur public. La conservation des données, du certificat local et des associations mobiles doit être contrôlée lors de la mise à jour.
